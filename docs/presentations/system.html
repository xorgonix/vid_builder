vid-build 0.01

System overview

Go · Chi · templ · HTMX · daisyUI · SQLite · Wails host · LM Studio · ComfyUI · FFmpeg

Non-negotiables

  • SQLite is the sole source of truth. Media lives on disk; the database holds rows, URIs and checksums.
  • Go is the application language. Server-rendered HTML is the interface.
  • HTMX is the default interaction. JavaScript only for local islands (blocking editor, uploads, shortcuts).
  • Human authority. AI proposes; a person applies, selects and approves.
  • Wails is a host, not the architecture. The same app runs in a browser.

Data model, in one picture

Workspace→ Project→ Video→ Section→ Scene→ Shot
Shot → start_frame spec Shot → end_frame spec Shot → motion spec
Spec → Generation request→ Attempt (immutable)→ Asset→ Selection / Assessment / Approval

Outline, Board and Edit are views over one ordered structure — no duplicated authority.

SQLite rules that keep it sane

  • PRAGMA foreign_keys=ON, WAL, bounded busy timeout, short writes.
  • STRICT tables; UUIDv7 text ids; UTC RFC3339 ms timestamps; integer ms durations.
  • JSON columns are CHECK(json_valid(...)).
  • Every mutable aggregate has an integer revision; updates require the expected revision (409 on conflict).
  • Partial unique indexes enforce “exactly one current” row: brief, spec per kind, selection per role, blocking per endpoint.
  • Attempts, approvals and audit rows are append-only.

Blocking: structured JSON → deterministic SVG

  • Schema: canvas, camera, zones, actors (pose/gaze/facing), props, labels, arrows — coordinates normalized 0..1.
  • Rendered by a pure Go renderer in internal/blocking; same input always yields byte-identical SVG.
  • Change analysis diffs start vs end: shot size, angle, position, pose, gaze, props, arrows.
  • Browser island edits and serializes back to JSON; a plain-text JSON fallback works with JavaScript off.

Prompt compilation is an application concern

  • Layers: project style, character, location, endpoint, motion, workflow, experiment.
  • Modes: inherit · append · replace · suppress · lock.
  • internal/prompt folds base + layers into exact positive/negative fields.
  • Source layers, compilation rule and final bound values are all stored — a better compiler can regenerate without losing intent.

Workflow ownership (the important split)

ComfyUI owns

  • the node graph
  • samplers, loaders, custom nodes
  • graph execution

vid-build owns

  • intent, prompt layers, references
  • which workflow, which target
  • bindings, submission, receipts
design in ComfyUI → export API JSON → import immutable version
→ confirm bindings → validate on target → compile → submit → capture receipt

No node graphs are constructed in Go. A missing node or input fails validation — it is never guessed.

Bindings, not hard-coded node ids

{
  "semantic_field": "first_frame_positive",
  "node_id": "2",
  "input_name": "text",
  "required": true
}
  • Vocabulary: first/last_frame_positive|negative, *_asset, motion_*, seed, width, height, fps, frame_count, model_name, lora_stack, output_node.
  • Import suggests bindings by node type; a human confirms them before the version is validated.
  • Validation checks node classes and checkpoints against a fresh target capability snapshot.

Generation pipeline

spec revision ─► generation request (frozen: workflow version, tier, candidates, seed policy)
             └─► attempts (immutable, one per candidate)
                   └─► job (durable, leased) ─► worker phases
validate → stage_inputs → load_models → submit → generate → collect → verify → persist → cleanup
                   └─► assets (checksum, receipt) ─► selections ─► approvals

Retry creates a new attempt. Receipts record model, workflow hash, resolved prompts, bound inputs, seed, timing, cost, peak VRAM.

Endpoint-conditioned motion invariant

  • A motion request marked requires_first_last cannot start unless:
    • both selected endpoint assets exist and match their checksums;
    • both are approved or exception-approved;
    • the chosen workflow declares first_frame_asset / last_frame_asset bindings.
  • The worker stages both frames to ComfyUI and records both checksums in the receipt.
  • No automatic start-only fallback. A start-only run is a different, deliberate request.

Adapters & targets

  • Contract: Capabilities · Estimate · Validate · Submit · Status · Cancel · Fetch.
  • Targets: local_comfy · remote_agent · hosted_comfy · commercial_api · local_tool.
  • Preflight compares request requirements to declared capability; unsupported settings warn explicitly and are recorded.
  • An adapter may not simulate an unsupported first/last, negative prompt, reference or LoRA.

Security

  • Argon2id password hashes; sessions stored only as SHA-256 token hashes.
  • Per-session CSRF on every mutation (including HTMX); workspace-scoped authorization in services, not just routes.
  • Loopback by default. Local services are allow-listed; ComfyUI is never reverse-proxied or exposed.
  • LAN access is off by default, enabled explicitly, with a single-use pairing code and per-device revocable sessions.
  • Secrets never enter SQLite, HTML, job payloads or receipts.

Media, backup, recovery

  • Atomic placement: temp write → checksum → rename → database commit. Relative forward-slash URIs; traversal rejected.
  • Thumbnails are derived assets (thumbnail_of), never untracked cache files.
  • Backup = consistent DB copy (VACUUM INTO) + media manifest with checksums; verify re-hashes every file.
  • Restore is an offline CLI: verify → safety copy → atomic swap → integrity check.

Durability & observability

  • Jobs are leased (lease_owner, lease_expires_at) and recoverable after restart.
  • Every phase emits a job_event; progress in basis points.
  • Measured execution_observations feed the compute estimates — assumptions are replaced by evidence.
  • Audit events and a transactional outbox (domain_events) record who did what.
  • Memory coordination frees planner VRAM before local GPU work and records the action.
