How a team works in vid-build

  • Workspaces per client
  • Roles and least privilege
  • Reviewer approves with a reason
  • Edit, export, package

Workspaces are the boundary

Personal work and each client live in separate workspaces. Authorization is enforced in the services, so nothing crosses a boundary by accident.

Roles, not shared logins

Owners, editors, reviewers and viewers. Reviewers comment, assess and approve; editors build. Every action is attributed to a person.

Approval is a decision, not a vibe

Approve, reject, or approve with a recorded exception. Model assessments are advisory and never approve on a human's behalf.

Questions studios ask

Does it run as a server for a team?

Yes. The same application runs as a real web app with workspaces, roles and per-device sessions, or as a local-first desktop tool.

Can reviewers use their own devices?

Owners pair devices over LAN with a short-lived, single-use code. Each device gets its own revocable session.

What happens to our data?

It stays with you: a single SQLite database and a media folder with checksums. Nothing is uploaded to us.

Can we hand a project to a client?

Queue a portable project package (schema version, project rows, referenced media, checksums and an import manifest) and hand it over.

Do we have to abandon our ComfyUI setup?

No. Keep authoring in ComfyUI. vid-build imports your graphs and binds only the inputs you confirm.
